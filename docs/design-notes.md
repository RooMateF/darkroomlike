## 0. 專案定位

- 核心玩法參考 *A Dark Room*:文字/符號呈現、資源管理為主軸
- 平台:網頁,單人開發、主要自己玩,但畫面設計要考量「上班偷玩」的輕量節奏(不需要長時間專注操作)
- 與 A Dark Room 的差異化重點:
  1. 中盤探索地圖要更大、更好玩
  2. 戰鬥系統要有深度,但避免變成「比誰按按鈕快」的反射遊戲(A Dark Room 後期的問題)
  3. 植入 AI 動態生成內容(寶箱/資源/NPC),但生成邏輯不能讓開發者自己也全部預知結果,要保留驚喜感

### 0.1 全域美術風格原則(已定案:純 ASCII)

- **所有畫面**(戰鬥、地圖探索、特殊怪物呈現等)一律只用 **ASCII 符號拼組**(如 `. ; : @ # $ %` 等),不使用圖片素材,連特殊怪物的呈現也走符號拼字這條路線
- 這不只是戰鬥 UI 的風格(見 2.7),而是**貫穿全遊戲的美術原則**,已經在戰鬥雛型(game/)實踐過一版(見 2.7 的黑白+ASCII 進度條),之後的地圖探索畫面(第 3 章)、任何新畫面都要延續同一套限制
- 好處:開發成本低(不需要美術資源)、跟「文字冒險/資源管理」的核心玩法基因一致,也呼應 A Dark Room 本身的呈現方式

## 1. AI 動態生成內容

### 1.1 分層策略(已決定採用 1+2)

| 層級 | 做法 | 成本 | 用途 |
|---|---|---|---|
| **1. 規則式生成** | 加權隨機表,依遊戲狀態(資源量、天數、已解鎖科技)動態調整機率分佈 | 免費、無延遲 | 決定「這個階段該出現什麼」,類似 RimWorld Storyteller / Left4Dead AI Director 的邏輯,但用寫死的規則實現 |
| **2. 離線預生成** | 開發期用 Claude API 批次生成寶箱描述、NPC 對話、事件文本,存成靜態資料池 | 一次性、幾美金內 | 遊戲執行時只從池子按規則抽取,零延遲、零持續費用 |
| 3.(保留,暫不做) 即時 LLM 呼叫 | 每次生成即時連 API(如稀有 NPC 客製對話) | 持續費用,Haiku 4.5 約 $1/$5 每百萬 token,單次生成成本可忽略但仍是持續支出 | 未來若想要「每次真的不一樣」的驚喜感才考慮加入 |

### 1.2 規則引擎架構(已定案:兩層權重模型)

**第一層:硬性門檻(決定能抽哪個內容池,不是抽多少)**
- **分區類型**(森林/廢墟/礦坑…)→ 決定主題池,不會在森林抽到礦坑限定的寶箱敘事
- **主線進度**(已擊敗的原始汙染數量)→ **軟性偏移,不完全鎖死**:未擊敗對應派系前,該派系的高階內容機率極低但非零,保留極少數提前遭遇強敵的驚喜/風險感,但風險要可控(需搭配保底/警示機制,避免玩家被雖低機率但致命的內容碾壓——具體保底手段待第 3 章地圖細節一併設計)

**第二層:軟性權重(決定池內機率分佈)**
- **探索深度**(該分區已探索格數/離基地距離)→ 越深、越稀有/越危險的內容機率越高
- **天數/遊戲進程** → 拉動整體強度曲線
- **點燈狀態**(3.7)→ 已點燈區域偏向較溫和的內容基調

**關於資源匱乏的動態難度調整(已定案:不做)**:
- 基地資源匱乏時,生成機率**不會**動態偏向補償玩家(不會多給資源類獎勵來緩解匱乏)
- 理由:呼應「苦中帶希望」的調性(worldbuilding.md § 4.1)——匱乏必須是真實的,系統不能偷偷幫玩家兜底,否則會削弱資源管理主軸的緊張感與玩家自己扭轉局勢時的成就感

**提前遭遇高階內容的保底/警示機制(已定案:文字氛圍預警,非數值保底)**:
- 不用明確 UI 警告(如「危險等級:高」的數值標示),改用**環境敘事文字**傳達不祥預感,例如「你感覺到前方有某種不可名狀的存在」「空氣忽然變得凝滯」之類的氛圍描寫
- 這個做法直接延續 2.9 節「不做明講式 turn preview,改用跑條速度傳達威脅」的 show-don't-tell 一貫原則,也完美對齊克蘇魯题材「無法被理性描述的恐懼」的氛圍調性(worldbuilding.md)
- 玩家看到這類文字提示後,有機會主動選擇撤退(3.10 撤退機制)——警示的作用是給玩家「知情選擇權」,而不是系統直接幫玩家擋掉風險,維持「匱乏與風險是真實的」設計原則(1.2)
- 這類警示文字本身也適合放進第 1 章的離線預生成內容池,依威脅等級分層準備一批固定文案(如低度不安 / 強烈不祥感 / 瀕死預兆等分級文字)

### 1.3 待辦

- [ ] 內容池的資料結構(寶箱描述、NPC 對話、事件文字各自要多少筆才夠用,分幾個「稀有度」/「地區風格」分層,含上述警示文字分級)
- [ ] 之後若要接 Claude API 批次生成內容池,流程另開文件記錄 prompt 設計

## 2. 戰鬥系統架構(半即時制)

### 2.1 核心排程模型:全域事件佇列

- 不用「每個角色各自輪詢計時器」,改用 **優先佇列(priority queue)**,依「下次行動時間」排序
- 每個「行動槽 Action Slot」(見 2.3)有自己的 `speed`,行動間隔 `interval = BASE_INTERVAL / speed`
- 排程佇列存的是「哪個槽、什麼時候該行動」,取出時間最小者執行,執行完把下一次時間 `current_time + interval` 塞回佇列
- 優點:速度比是小數也不會有誤差累積,效能好(只處理事件點,不逐 tick 掃描)

### 2.2 速度比例設計(已定案)

- **敵方行動次數 = 傷害輸出倍數**(如 5 次行動 = 5 倍傷害),但實際速度差距會控制在小範圍
- 範例:速度 20 : 25 → 1.25 倍行動頻率差距,而非誇張的 1:5
- 因為比例壓在小範圍,**單次命中傷害可以維持相對固定值**,不需要额外做「速度→傷害反向補償」的複雜公式
- 平衡重心留給裝備/技能造成的策略差異,而非速度數值本身的懲罰機制

### 2.3 玩家與同伴的行動複雜度分工(已定案)

- **同伴/NPC**:只有單一固定節奏的自動行動,不開放操作介面,不會有多種攻擊模式,單純照自己的速度規律行動,不是勝敗關鍵、只是加成輸出
- **玩家**:唯一擁有完整多類別行動系統的角色,戰鬥深度全部集中在玩家身上

### 2.3.1 玩家四大行動類別(固定四條主跑條)

```
冷兵器 [▓▓▓▓▓▓▓▓░░] 80%
熱武器 [▓▓▓░░░░░░░] 30%
法術   [▓▓▓▓▓▓▓▓▓▓] 100% ← 待命中
道具   [▓▓░░░░░░░░] 20%
```

- 排程單位是「類別」,每個類別底下可以容納**多個子行動**(如法術類別下有 A、B 兩種法術,各自速度不同)
- 這個結構取代了原本「每武器各自獨立行動槽」的模型,詳見 2.3.2 的共享重置機制

### 2.3.2 類別內「共享重置」機制(核心創新,取代原本的雙持武器分歧點)

以法術類別、A/B 兩種法術為例:

1. 子行動各自獨立計時(A、B 速度不同,各自累積自己的進度)
2. 任一子行動跑滿時,觸發決策點(沿用 2.6 的 Wait 模式暫停),打開該類別選單,顯示「已跑滿的A」與「還沒跑滿的B」
3. 玩家選擇 **使用A** → 整個類別(A、B)的計時器**一起歸零重新開始**
4. 玩家選擇 **暫不使用** → 選單關閉、模擬時鐘繼續推進,A 維持在 100% 待命(不消失、不衰減),直到玩家之後主動點開使用,或 B 也跑滿時再次觸發決策點

這個機制回答了原本「雙持武器獨立 vs 共用行動點」的開放問題,是兩者的折衷:子行動各自獨立計時(能看出速度差異),但共享同一個「使用即重置全部」的節奏池,逼玩家在「現在用快的A」與「賭一把等更強的B」之間做節奏博弈。

**已定案:四大類別(冷兵器/熱武器/法術/道具)通用套用這套「共享重置」規則**——例如冷兵器類別下若同時有「輕擊」「重擊」兩種招式,也遵循同一套邏輯(各自獨立計時、任一跑滿觸發決策點、使用後整個類別一起歸零)。這代表排程核心只需要實作一套「類別 + 子行動」邏輯,四個類別共用同一份程式碼,不需要為每個類別寫特例。

### 2.4 行動花費差異化(後期系統)

- 每個「行動」有自己的 `base_cost`(以 BASE_INTERVAL 為單位,如快速攻擊 0.5、重擊 2.0、詠唱 3.0)
- 實際花費:`actual_cost = action.base_cost / character.speed_multiplier`
- 「角色速度」是全域縮放係數,「行動類型」是額外乘數,兩者獨立又能疊加

### 2.5 額外行動裝備

兩種實作方式,尚未選定:

- **降低門檻型**:裝備讓特定行動 `base_cost` 打折,簡單但要注意跟速度疊加會不會乘法爆炸
- **額外插入型**:裝備賦予「每 N 次正常行動後,額外插入一次不消耗排程的行動」,更明確但排程邏輯要獨立處理避免混淆

### 2.6 避免「比誰按更快」(核心設計原則,已定案)

- **玩家可操作的行動槽跑滿時,模擬時鐘立刻暫停等待輸入**,敵方時鐘同步停止,不會偷跑
- 進度條在視覺上可以持續即時跑動(製造節奏感/緊張感),但**絕不會逼玩家在有限時間內反應**——跑滿只是「觸發決策點」,不是「開始倒數」
- 等同 FF7 的 Wait 模式邏輯,且**不開放 Active 模式**,直接鎖死在設計裡,徹底避免 A Dark Room 後期「純按鈕反射」的問題
- 暫停期間其他(未輪到決策的)行動槽仍可視覺跑動,但不會真的觸發行動,直到玩家做完當前決策才繼續推進

### 2.7 UI / 呈現方式

**進度條(核心視覺)**

```
左輪手槍 [▓▓▓▓▓▓▓▓░░] 80%
佩刀     [▓▓▓░░░░░░░] 30%
哥布林A  [▓▓▓▓▓▓▓▓▓▓] 100% ← 即將行動
```

- 每個行動槽一條,堆疊呈現,不同武器/角色/敵人並列
- 用進度條差異直接傳達「節奏差異」,不需要真動畫

**戰鬥 Log(簡約風格 + 輕量 CSS 動畫,已細化)**

```
[你] 佩刀 >>> 哥布林A  (-6)
[哥布林A] »»» [你]  (-3, 格擋)
[隊友-小林] 左輪 · 砰 → 哥布林B (-8, 爆擊!)
```

- 不同武器用不同符號區分手感:`>>>` 揮砍、`»»»` 快速射擊、`·砰` 開槍音效字
- 保持簡約,避免 log 過長拖慢「偷玩」節奏
- **已定案**:逐條顯示 + 捲動限制——每個行動都完整顯示一條 log(含符號動畫),但畫面只保留最近 3–5 條,較舊的自動捲出,兼顧臨場感與閱讀節奏(見 2.12)
- **不是純靜態文字**,每條 log 疊加兩層輕量動畫:
  1. **攻擊符號位移**:`>>>`/`»»»` 從攻擊者名字後快速滑動到目標名字前(`transform: translateX` + `ease-out`,時長 100–150ms,不同武器可有不同滑動速度/軌跡感,但都要快)
  2. **受擊目標震動**:命中瞬間目標文字(如「哥布林A」)觸發 `shake` keyframe(左右小幅位移,150–200ms),震幅建議跟傷害/是否爆擊掛鉤,增加資訊量而非純裝飾
- 技術上用純 CSS transform/opacity 動畫(不用 canvas/WebGL),每條 log 是獨立 DOM 元素、動畫為一次性觸發,成本極低,確保在一般辦公電腦上也不卡

### 2.9 敵方行動預告(已定案:不做明講式 turn preview)

- **不**用文字/UI 明確預告敵方下一步要做什麼
- 改用**進度條速度本身傳達威脅資訊**:敵方單位的跑條速度依「當前準備中的招式」而變動,招式越痛、越危險,跑條就越慢
- 玩家透過觀察敵方跑條的快慢節奏,自行判斷「這一下會不會很痛」,不需要文字說明,符合遊戲一貫的 show-don't-tell 呈現風格
- **架構意涵**:敵方的排程模型跟玩家不同——玩家是「固定四類別 + 子行動共享重置」(2.3.1–2.3.2),敵方則是「AI 先選定本次要出的招式,再依該招式的 cost 決定這次跑條速度」,每次行動後可能會用不同速度重新起跑(不像玩家子行動各自固定速度累積)

### 2.10 撤退機制(已定案:隨時可撤退,有風險)

- 任一玩家決策點都能選擇「撤退」,不限定要消耗特定道具
- 撤退有失敗風險(如撤退失敗會被追擊一次、吃一次免費傷害),具體風險數值(失敗機率、追擊傷害公式)之後再訂
- 定位:提供戰略彈性(打不過可以跑),但不是零成本的安全閥,維持戰鬥的緊張感

### 2.11 敵方 AI 目標選擇邏輯(已定案:威脅值優先)

- 敵方優先攻擊「最近造成最多傷害/威脅」的目標(玩家或隊友皆可能被鎖定)
- 隊友因此有被集火的可能,存在感與風險感更真實,也讓玩家的輸出節奏會實際影響敵方注意力分配(打越猛越容易被針對)
- 威脅值的衰減/計算公式(如是否隨時間衰減、治療是否算威脅)之後再細訂

### 2.11.1 道具類別範疇(已定案:多樣化,不只治療)

道具類別(2.3.1)確認涵蓋多條產品線,不是只有治療:

| 類型 | 範例 | 效果方向 |
|---|---|---|
| 治療類 | 繃帶、藥膏 | 恢復生命 |
| 防護類 | 一次性護罩裝置(科技系) | 短暫抵擋傷害 |
| 攻擊類 | 手榴彈(科技系) | 範圍傷害 |
| 控場類 | **絆繩** | **降低敵方行動槽的累積速度**,直接針對 § 2.1 的排程節奏做文章 |
| 魔法卷軸 | 一次性施放特定法術 | 讓玩家能用**還沒解鎖的魔法系別**效果,是「法術零散收集」(worldbuilding.md § 6.1)系統外的另一條管道 |

**設計意涵**:道具類別因此同時涵蓋「數值向」(治療/攻擊)跟「節奏向」(控場,如絆繩)兩種手感,不會被戰鬥類別的其他三類(冷兵器/熱武器/法術)完全取代——控場類尤其重要,因為排程系統(2.1–2.9)的核心就是節奏,一個能直接干預敵方跑條速度的道具,價值不會輸給純粹的傷害數值。配方沿用 resources.md 的既有素材線,不需要另開新資源類別。

### 2.11.2 異常狀態系統(已定案:累積制,非機率制)

**核心機制**:
- 每種異常狀態有自己獨立的「異常值」計量,初始為 0
- 造成該異常的攻擊/技能,依來源強度增加一定異常值(普通攻擊少量、專精技能多量)
- 異常值累積到門檻(草案:每次 +10,門檻 100,即 10 次疊加觸發)時,觸發該異常的**一級**效果,計量歸零重新累積
- 再次累積滿門檻 → 升級到**二級**;第三次滿門檻 → **三級**(封頂,不再繼續疊加)
- 一段時間沒有繼續疊加,異常值可自然衰減(避免單次爆發就卡死在高級異常,衰減速率待補)

**設計意涵**:完全不吃機率,呼應整個排程系統「不靠 reflex、不靠運氣,靠資源與節奏管理」的哲學——異常狀態變成「有沒有持續打某個屬性」的策略問題,不是「這次會不會觸發」的賭運氣問題。

**候選異常狀態清單(草案,待你從中挑選/調整三級具體效果)**:

| 異常 | 概念 | 可能來源 |
|---|---|---|
| 中毒 | 持續傷害 | 瘟疫/腐蝕系、生物咬傷 |
| 麻痺 | 部分行動槽停止累積 | 電磁系 |
| 目盲/幻惑 | 命中率下降,或看不到敵方跑條資訊 | 幻惑系 |

### 2.13 角色屬性與成長系統(已定案:無等級制,四項屬性)

- **玩家不設等級/經驗值系統**——沒有練功升級這件事
- **武器熟練度(每種武器類型獨立)**:針對特定武器類型(如冷兵器裡的某把劍、熱武器裡的左輪)使用越多,該武器的熟練度越高,**只影響該武器自己的行動槽跑條速度**,不影響傷害或其他數值,也不影響其他武器
- **防具驅動的數值堆疊**:生命值上限、基礎速度、異常抗性(2.11.2)這類數值的提升,主要靠**打造/穿戴防具**取得,不是角色升級的產物——呼應第 5 章的裝備打造邏輯(resources.md),讓「變強」這件事完全體現在探索與資源投入上,而不是抽象的等級數字

**玩家角色本身只有四個屬性維度**:

| 屬性 | 說明 |
|---|---|
| 生命值(HP) | 由防具/裝備堆疊,無等級加成 |
| MP | 法術消耗用的曖昧數值(worldbuilding.md § 6) |
| 速度 | 基礎速度(防具/裝備影響)+ 各武器熟練度帶來的**該武器專屬**加乘 |
| 異常抗性 | 對應 2.11.2 異常狀態系統,降低異常值累積速度或提升衰減速度 |

**架構意涵**:這代表戰鬥引擎(game/src/engine.ts)裡原本單一的 `playerSpeed` 全域倍率,之後要拆成「基礎速度」+「各子行動各自的武器熟練度倍率」兩層疊加,而不是單一全域數字——武器熟練度是每個子行動(2.3.2)獨立累積的隱藏成長值,先記錄在這裡,等回頭擴充戰鬥雛型時再實作。

## 3. 地圖探索系統(半手做分區地圖)

### 3.1 整體方向(已定案)

採**半手做分區地圖**:幾個手工設計風格的區域(如森林、廢墟、礦坑),每區有手設的地標/事件,敘事感優於純程序生成,但保留 3.3 的資源消耗機制維持重複遊玩的策略深度。

### 3.2 分區內部呈現(已定案:網格地圖 + 符號移動)

- 類似 A Dark Room 的 outside 世界地圖,但範圍更大
- 玩家操控一個符號在網格上移動,移動過程中逐步揭露地形/事件(類似戰爭迷霧)
- 視覺上最貼近「地圖探索」的直覺感,符合整體文字+符號的呈現風格
- 遵守 § 0.1 全域 ASCII 原則,不使用圖片,連特殊怪物的呈現也走符號拼字

**符號說明(草案)**:

```
  ' ' 未探索(迷霧)
  .   已探索平地
  ;   草叢/灌木(遭遇機率略高)
  :   碎石/廢墟地形
  #   障礙物(不可通行)
  ~   水域
  @   玩家目前位置
  S   補給點/前哨站(檢查點,§3.9/§3.10)
  $   資源採集點
  *   事件/寶箱(填充層生成)
```

**範例(補給點靠近出發點密集,越外圍迷霧比例越高,呼應 §3.10 補給點密度曲線)**:

```
        . . ; ; #
      . . @ . ; : :
    S . . . . : : #
      . . $ . : ~ ~
        ; . * . ~
          ; ; . .
```

特殊怪物在遭遇畫面也走同一套符號拼字邏輯呈現輪廓,不使用圖片素材,具體怎麼拼視覺效果最好留待美術細化時再試。

### 3.3 分區間連接(已定案:中心基地輪輻式)

- 玩家以**基地為中心**,可自由選擇前往任一已發現的分區,探索完可隨時返回
- 不是線性推進、也不是同時全部解鎖的開放分層,而是「基地↔分區」的輪輻(hub-and-spoke)結構
- 這個結構跟資源管理主軸緊密掛鉤:帶資源回基地卸貨、補給後再出發,形成穩定的「探索—歸還—再出發」循環

### 3.4 探索成本(已定案:消耗實體資源)

- 每次在分區內移動/停留,消耗身上攜帶的實體資源(食物/水/火把等)
- 讓「探索」與「基地資源生產」緊密連動——資源生產效率會直接限制探索的深度與範圍
- 之後需要設計:攜帶容量上限、不同分區的消耗速率差異(如礦坑可能特別耗火把)、資源耗盡時的懲罰(強制返回?即時傷害?)

### 3.5 探索模式(已定案:玩家親自帶隊,不開放派遣)

- 探索由玩家角色親自推進,遇到戰鬥直接套用第 2 章已定案的四類別戰鬥系統,不需要額外設計「派遣同伴 AI 自動採集」這類獨立子系統
- 體驗上更集中、一致,開發範疇也因此收斂(不用另外做一套非戰鬥的 AI 決策邏輯)
- 助力型同伴**會一起進入分區同行**,技術細節見 3.6

### 3.6 同伴的探索/戰鬥整合(已定案)

- 助力型同伴(2.3 提到的「只有單一固定節奏自動行動」角色)**跟玩家一起進入分區探索**,不侷限於基地崗位
- **技術實作上,同伴被視為玩家戰鬥系統裡「額外的一個行動/武器」**——沿用 2.3.1–2.3.2 的「類別 + 子行動」排程架構,同伴的貢獻等同於多一條進度條/子行動,而不是另外設計一套獨立的同伴 AI 決策系統
- 換句話說:排程核心完全不用區分「這是玩家的武器」還是「這是同伴的攻擊」,兩者用同一套底層資料結構,只是同伴的子行動預設自動觸發(不佔用玩家的決策點),工程實作與 UI 呈現都能高度復用既有系統

### 3.7 地圖與戰鬥銜接(已定案:隨機遭遇,可後期壓制)

- **不**採「網格上踩到敵人符號才觸發戰鬥」,改用**隨機遭遇機率**:在分區內移動/停留時,依機率觸發戰鬥,不會在地圖上直接看到敵人符號
- **區域點燈機制(後期壓制手段)**:玩家可以消耗較多資源,對特定範圍進行「點燈」,降低該範圍內的遇敵機率
  - 定位:不是免費的安全區,是要用資源換安全性的後期投資選項,呼應資源管理主軸
  - 待確認細節:點燈效果是永久性還是會隨時間衰減需要維護?遇敵機率降到多低(完全歸零 vs 只是降低)?點燈範圍大小怎麼定義(以格數計算?)

### 3.8 多地圖節點系統(新增架構層級:地圖之上還有地圖)

這是比原本設想更高一層的結構——世界不是「一張大地圖裡分好幾區」,而是**多張獨立地圖,彼此透過節點連接**,每張地圖有自己的分區與自己的基地。

- 玩家在地圖 A 完全探索完成後,可以前往下一個**地圖節點**(地圖 B),地圖 B 是全新的一整張地圖(有自己的分區系統,見 3.1–3.7)
- 抵達新地圖後,基地的處理方式**已定案為玩家自由二選一**(移除原本的「搬遷原基地」選項,不再有三選一):
  1. **原地重建**:在新地圖從零開始蓋基地,最陽春但隨時可行
  2. **開啟地圖捷徑(鐵路)**:見 3.8.1,花費資源建立通往其他地圖的鐵路,大幅降低移動成本

  **自由選擇的敘事理由(已定案,呼應 worldbuilding.md § 8)**:玩家是從「一片漆黑的營地」出發,對世界一無所知,只能自己四處碰壁探索——路上可能遭遇發狂變異或被生物殺死,但舊日支配者的代行者會將主角復活到營地(死亡機制見 3.9)。因為探索本質上是無方向的試錯,所以地圖節點的推進與基地處理方式**不會被系統強制引導成固定順序**,完全交給玩家自行摸索決定。

- **地圖 A 探索完後前往地圖 B,地圖 A 仍可以回去**(已定案,不會封存)。回訪同樣走 3.8.1 的鐵路捷徑機制,不會在地圖 A 額外建立次要營地

- 這個系統讓「地圖大不大」不再只靠單張地圖的網格尺寸撐場面,而是用**多地圖串接**創造規模感,同時保留 A Dark Room 那種「不斷往下一階段推進、舊地圖逐漸退居資源後盾」的節奏

### 3.8.1 捷徑網(鐵路系統,已定案)

呼應世界觀「戰前留下的工業科技殘骸」基調(worldbuilding.md § 5、§ 10),捷徑具體化為**鐵路**:

- **資料結構**:簡單的點對點圖——每條鐵路是一條邊,只連接兩個特定地圖節點(A↔B),不是解鎖後可任意傳送的萬能捷徑。若 A↔B、B↔C 都有鐵路但 A↔C 沒有,就沒有直達路線,要嘛繞道 B、要嘛走正常的地圖間移動方式,不需要額外的尋路演算法,保持系統單純(呼應 § 5.1 基地經營維持簡單迴圈的原則)
- **建造成本**:一次性花費資源+時間才能建成一條鐵路,呼應「大幅降低移動成本」是有代價的後期投資
- **通行成本(已定案,重要修正)**:鐵路建成後**通行不是免費的**——每次搭乘鐵路移動,仍要消耗一定量的**煤等資源**。這讓捷徑網從「一次性投資、永久免費」改為「基礎建設 + 持續營運成本」的模型,更貼近鐵路的真實邏輯,也讓資源管理主軸持續介入中後期的地圖間移動決策,不會因為捷徑建好就完全脫離資源壓力

### 3.8.2 鐵路的第二種用途:連接資源據點(已定案,擴充鐵路系統)

鐵路不是只能連接「地圖之間」,也可以連接**中心基地 ↔ 分區內已發現的特定資源據點**(如鐵礦坑),兩種連接方式共用同一套點對點資料結構(§3.8.1),差別在效果:

- **地圖↔地圖鐵路**:快速往返移動,每次通行消耗煤(§3.8.1 已定案)
- **基地↔資源據點鐵路(新增)**:建成後**變相提升該據點的開採效率**(例如指派給該礦坑的礦工產出提升),定位是把「每次都要出門探索才能開採」轉變成「永久性的產能延伸」,呼應 A Dark Room 中後期把外部據點整合進生產鏈的節奏
- 這種資源據點鐵路**不需要每次通行消耗煤**——它代表的是永久性基礎建設對某個已知據點的效率强化,而不是玩家角色本身的移動行為,跟地圖間鐵路的「每次搭乘都是一次实际移动」性質不同

### 3.9 死亡與資源耗盡懲罰(已定案:仿 A Dark Room 的迷霧重置機制)

- 探索中資源耗盡(或戰鬥落敗死亡)時,**回到最後一次從據點(補給點/前哨站,§3.10 骨架層)出發前的狀態**,不是整張分區地圖從頭重置——補給點因此天然具備「檢查點」的功能,途中已揭露的迷霧、走過的路徑,只回退到「離開最後一個據點」的那個瞬間,而非回退到「進入整個分區」的最初
- **玩家「復活」重新開始**
- **敘事上的解釋**(呼應 worldbuilding.md § 8):這個復活機制不是單純的遊戲系統抽象,而是**舊日支配者的代行者主動把主角救回營地**——死亡在劇情上被詮釋為「代行者的介入」,而非單純的 game over 重試,讓死亡懲罰自然嵌入敘事而不顯得突兀
- 定位:懲罰足夠讓玩家在意(白費從最後據點出發後的探索進度),但不是永久性失去角色/存檔的硬核死亡,維持整體「苦中帶希望」的調性(worldbuilding.md § 4.1)
- **物品損失規則(已定案)**:
  - **探索時隨身攜帶出發的物品(食物/水/彈藥等消耗品)全部消失**——視同這趟失敗的行程真實消耗掉了
  - **探索途中拾獲、但尚未帶回據點/基地的戰利品,回到原本被拾獲的位置**——不會被憑空刪除,只是「這次沒有成功帶出去」,下次重新探索到該處時仍可拾獲,呼應迷霧與地圖狀態整體回退的邏輯
- **重要:這個復活保護只適用於玩家本人**——隨隊同伴戰死時**不會**一併被代行者救回,是永久性損失,詳見 5.2「同伴的永久死亡風險」。也就是說同一次探索失敗,玩家本人毫髮無傷地復活,但當次戰死的同伴不會隨之復原——死亡懲罰對玩家與同伴是不對稱的

### 3.10 AI 生成內容 × 分區地圖整合(已定案)

**骨架層 vs 填充層分工(已定案)**:

| 層級 | 內容類型 | 產生方式 |
|---|---|---|
| **骨架層(手工)** | 地標事件、見證者(worldbuilding.md § 8.1)、教派營地、Boss 戰場、劇情觸發點、**補給點/前哨站** | 固定位置,手工設計,不受生成規則影響 |
| **填充層(AI/規則生成)** | 資源採集點、寶箱、小型隨機事件、雜兵(隨機遭遇) | 依 § 1.2 兩層權重規則動態產生 |

**補給點密度曲線(已定案,參考 A Dark Room 的前哨站設計)**:
- 骨架層額外納入**補給點(前哨站)**——這是手工放置的固定據點,可以在探索途中補充/暫存資源,不需要走回中心基地
- 補給點密度**隨離基地距離遞減**:靠近基地(或分區入口)的地方補給點密集,前期裝備能力較弱時容錯空間大;越往地圖外圍,補給點越稀疏
- 這個密度曲線直接製造出核心決策張力:**是否要消耗更多資源繼續深入迷霧,還是趁還有餘裕趕緊止損返回**——距離基地越遠,這個決策的風險就越高,天然形成「淺嚐輒止的安全探索」vs「賭一把深入换取稀有內容」的策略選擇

**填充層的運作時機(已定案:即時生成,細節待補)**:
- 傾向**揭露時即時 roll**(玩家移動、迷霧被揭開時才決定該格內容),而非地圖產生時就全部決定好——這樣「探索深度」等變數能反映玩家實際走的路徑
- **重要限制(已定案)**:即時生成的寶箱內容**只能是普通資源**(基礎素材,不含稀有法術碎片/外星科技/特殊道具等)。理由:即時生成若能產出稀有內容,搭配 3.9 的迷霧重置機制(死亡後迷霧重置、重新探索),會變成可重複刷取稀有內容的漏洞;把稀有內容留給骨架層(固定位置、只會給一次)可以避免這個問題,也讓「稀有戰利品」保有敘事重量,不會被刷成純數值資源

### 3.10.1 特殊探勘地點五級制(已定案)

地圖上「踩到後需要深入調查的點」統一分五級,內部是**小地城結構**:進入後打一場,選擇「繼續深入」數次,最深處是 Boss(層數隨等級增加)。Lv4/5 用敘事警示(「這裡散發著危險的氣息……」)提醒玩家做好準備,不用 UI 數值標示。

| 等級 | 定位 | 數量/距離 | 打通後 |
|---|---|---|---|
| **Lv1** | 一般地點 | 最多,散佈各處 | 成為**前線基地**:補給水與糧食 |
| **Lv2** | 資源開放地點 | 離基地不遠 | 開啟特定資源;後期鐵路開過去可**強化資源獲取** |
| **Lv3** | 較強的遺跡 | 中距離 | **豐厚資源獎勵**,同時成為前線補給基地 |
| **Lv4** | 有名字的地方(鐵礦坑/觀測台/祭壇) | 較遠,需規畫路線與資源 | 中盤級強力裝備/道具/職業解鎖 |
| **Lv5** | 有名字、幾乎無法戰勝 | 最遠/最險 | 本章鑽研到極限才有機會打贏;最高級的獎勵 |

- 進入方式:踩上地點只顯示敘事與危險氛圍,**由玩家主動選擇「深入調查」才開戰**——不會踩到就被拖進戰鬥
- 層數進度持久化:打到第 2 層退出/戰死,下次回來從第 2 層繼續
- 失敗不鎖死,可以反覆挑戰

#### 3.10.2 補給網與攻堅節奏(2026-08 全流程模擬定案)

用機器人跑真實引擎全流程(見 `src/sim/full-run-bot.ts`)後定案的一組相互咬合的規則:

- **哨站鏈**:通往四大地標的路線上各固定兩座 Lv1「舊哨站」(確定性擺點,約在路程 42%/75% 處)。沒有它們,地標外圍是超過水袋上限的無補給區,**物理性不可達**;玩家必須一站一站打通、把水量網路修出去(ADR 式前哨推進)
- **解放後的地標也是據點**:補水補糧、記檢查點。第一次進攻仍是「不打贏就回不了家」的單程豪賭——Lv4 到場警語「沒有準備就進去的人,恐怕回不來」是字面意思
- **據點休整**:抵達據點時若重傷,自動啃肉乾回血(每份 +4,回到八成上限,保留 2 份)——否則殘血抵達據點只是「補了水的殘血」,死亡螺旋照舊
- **遭遇率 0.10/步**(原 0.15):實測每場雜魚戰平均耗 10~16 HP;0.15 時每 9~10 步一戰,60 步往返需 60~90 HP 續戰力,Lv4 在數學上到不了。0.10 → 約 13 步一戰,深入有壓力但補給鏈撐得住
- **教堂守衛 hp 110**:滿血鐵裝+肉乾 14 的單場勝率約 55%,疊上前三層消耗與單程風險,整體攻堅成功率約 2~3 成——「本章極限」的定位
- **異質短刃 lootOnly**:不可打造(「這個時代做不出來」),cost 僅作修理費基準
- 地圖理論揭露上限約 93%,最外圈邊角落在補給網外,是這一章刻意留下的黑暗

#### 3.10.3 後期三系統(2026-08 定案實裝)

- **交易所**(木 1500/石 800;撿過異晶+外出過才浮現):異晶兌換稀有物資——繃帶(3 晶)/火焰卷軸(6 晶)/舊時代藥劑(10 晶,戰鬥中 +15 並解除所有異常)。解決卷軸全遊戲僅 2 卷、死亡即絕版的脆點;打怪(異晶)因此有獨立的長期收益線

## 4. 世界觀與風格設定

### 4.1 整體調性(已定案:中間調,苦中帶希望)

- 世界確實危險、人命關天,但**每次探索/建設都是實質的希望積累**,不是純粹的絕望生存,也不是輕鬆冒險沙盒
- 這個調性會回頭校準很多既有設計的手感,例如:
  - 戰鬥的緊張感(2.6 Wait 模式、2.10 撤退機制)要維持「有風險但可控」,不宜做到讓玩家覺得毫無勝算
  - 資源管理的匱乏感要「緊繃但有累積感」,不是純懲罰式的絕望曲線
  - AI 動態生成的內容(第 1 章)語氣基調也該對齊——寶箱/事件文本不宜過度陰鬱或過度輕浮

### 4.2 世界觀設定(已展開,另立文件)

完整的克蘇魯神話背景世界觀(外星文明、外神、月球/地球汙染起源、魔法原理、第三次世界大戰、主角身世、主線目標)已整理至獨立文件:**[worldbuilding.md](./worldbuilding.md)**

重點摘要:
- 外星文明狩獵外神,戰鬥餘波使外神軀體碎片墜落月球與地球
- 地球四塊碎片分別轉化出「深淵之王」「原初魔女」「瘟疫之主」「深淵與表面世界的分界」四大原始汙染
- 外星科技殘骸導致地球軍武暴走,引爆第三次世界大戰,人類退回接近原始時代(對應冷兵器)
- 少數感染者突變出操控原子震動(溫度)的魔法能力(對應法術類別)
- 主角是虛弱「舊日支配者」派出的代行者,主線為重建人類秩序、討伐地球四大汙染、最終挑戰月球汙染

### 4.3 核心威脅

四大原始汙染(地球)+ 月球外神碎片(終局),詳見 worldbuilding.md § 4、§ 9。四大汙染很適合對應第 3 章的多地圖節點系統(§ 3.8)——每個汙染各自坐落一個地圖節點,討伐順序與地圖連接方式待一併決定(worldbuilding.md § 11 已列入開放問題)。

## 5. 基地經營系統

### 5.1 核心迴圈(已定案:沿用 A Dark Room 簡單模型)

- 基地經營**不追求機制深度**——蓋建築解鎖工作、人口分配到工作、工作自動產出資源,直接沿用 A Dark Room 的簡單迴圈
- **深度全部集中在戰鬥系統**(第 2 章),基地經營的定位是穩定的資源後盾與節奏調劑,不是策略挑戰的主戰場
- 這個決定收斂了開發範疇,避免資源管理系統過度複雜跟戰鬥系統互搶設計重心

### 5.1.1 科技樹解鎖原則(已定案:探索發現優先於研究解鎖)

- 建築/工作類型的解鎖**不是靠抽象的「科技研究」**,而是**必須先在探索中實際碰到對應的資源據點**,才會在基地開放相應的工作分配——直接沿用 A Dark Room 的模式(如探索中找到鐵礦坑,才能把村民轉為礦工)
- 這代表科技樹的推進節奏跟地圖探索(第 3 章)緊密綁定,不是關在基地裡點數就能點出來的東西,逼玩家持續出門探索才能擴張經濟規模
- 呼應 resources.md § 9.1 的產出角色(伐木者/採石者/礦工等),每一種都預期要先在世界裡發現對應據點才能解鎖指派

### 5.2 兩種人力的區分(已定案:村民 vs 同伴)

遊戲中的「人」分成兩個性質完全不同的池子,不要混為一談:

| | **一般村民(人口)** | **同伴(Companion)** |
|---|---|---|
| 定位 | 資源的一種,大量、無名、可替換 | 具名角色,少量、有各自的戰鬥功能 |
| 參與生產 | ✅ 分配到建築工作,自動產出資源(5.1) | ❌ 不參與建設資源產出 |
| 隨隊探索 | ❌ 不會離開基地 | ✅ 可帶出門,見 3.6(戰鬥系統裡是額外行動/武器) |
| 留守時的作用 | 純生產力 | 影響**村莊隨機事件**(見 5.3) |

**設計意涵**:一般村民就是 A Dark Room 那種「數字化人口」,不需要個別敘事;同伴則是有名字、有戰鬥定位的角色,他們的存在感建立在「戰鬥功能」與「留守時的村莊保護」上,而非生產力。這讓玩家每次出門前都要做取捨:帶哪個同伴出去打仗、留哪個同伴看家。

**同伴的取得方式(已定案:主線劇情固定安排,精心設計的少數角色)**:
- 同伴**不是**可透過探索隨機抽取或 AI 內容池生成的量產角色,而是跟隨主線劇情**固定登場**的少數具名角色(如打倒某教派/解開某段劇情後加入)
- 這代表同伴的人數規模較小、但每個都值得投入獨立的人物設計、對話與背景故事,適合對應 worldbuilding.md 第 7 節「教派內部有善良的人也有瘋狂的人」——同伴很可能就是各教派中選擇脫離瘋狂、加入主角陣營的個體

**同伴的永久死亡風險(已定案,重要機制)**:
- 帶同伴出門探索時,同伴**有可能戰死,而且不會被代行者復活**——這點跟玩家本人的死亡機制(3.9)完全不同
- 玩家死亡 = 代行者介入、探索重置、玩家安全復活(3.9);**同伴死亡 = 永久失去**,不在代行者的保護範圍內
- 這讓「帶哪個同伴出門」變成一個真正有風險的敘事賭注,而不只是數值上的戰力選擇——呼應整體「苦中帶希望」的調性(worldbuilding.md § 4.1):希望的累積是真實的,但代價也可能是真實且不可逆的

### 5.2.1 一般村民的取得方式(已定案:仿 A Dark Room 自然成長模型)

- 村民數量隨基地狀態(住房/糧食等容量條件)**自然成長**,不需要主動「招募」操作,直接沿用 A Dark Room 的簡單模型(呼應 § 5.1 核心迴圈維持簡單)
- 村民也可能因為**突發事件而減少**(呼應 § 5.3 的村莊隨機事件,如瘟疫、天災等),形成「自然成長 vs 事件耗損」的動態平衡,不需要額外的招募玩法
- 這個決定讓一般村民維持「資源化人口」的定位(§ 5.2 表格),不會跟同伴(具名角色,主線劇情固定安排)的取得邏輯混在一起——兩者的獲取方式刻意做成完全不同的兩套機制,呼應兩者性質上的區隔

### 5.3 同伴留守時的村莊隨機事件影響(已定案)

- 玩家外出探索時,基地會有機率觸發**隨機事件**(人口削減、瘟疫爆發等負面事件,呼應 A Dark Room 的村莊事件設計)
- **留守的同伴會降低這些負面事件的削減幅度**:例如降低人口削減量、降低瘟疫造成的損失
- 同伴在此扮演的是「風險緩衝」角色,而非生產者——呼應 5.2 表格「不參與建設資源產出」
- 具體來說,這代表每個同伴除了戰鬥定位(3.6)外,還應該有一個**留守被動效果**(如「降低瘟疫損失 X%」),這兩種價值(帶出門 vs 留守)要在數值上大致平衡,避免出現「某同伴放家裡完全打不贏帶出門的價值」這種明顯不平衡的選擇

### 5.4 同伴永久死亡的中期復活機制(已定案:中期可用高成本資源復活)

- 同伴戰死不再是絕對不可逆——**遊戲中期解鎖後,可花費較大量的資源將同伴復活**
- 建議的設計方向(提案,供你調整):
  - **早期不開放**:遊戲初期同伴戰死依然是真正的永久損失,維持前期「每個決定都有真實重量」的張力;復活選項要到中期才解鎖,呼應「玩家對世界觀/魔法/舊日支配者的理解逐漸加深」的敘事節奏(worldbuilding.md § 8 的碎片化揭露)
  - **解鎖條件**建議綁定劇情或建築(如基地蓋出某個特殊設施、或觸及某段主線劇情後才開放復活的可能性),而不是單純「湊夠資源就能用」,讓復活本身也是一次敘事節點,不只是數值兌換
  - **資源成本**建議取自**探索地圖才能取得的稀有素材**(而非基礎產出資源),這樣能讓中後期的高難度探索有明確的資源出口(避免資源生產到後期沒地方花),也讓「賭上去救回同伴」跟「拿去點燈/升級裝備」形成資源分配上的真實取捨
- **待你確認**:復活是否有次數限制(每個同伴只能救一次,再死就真的永久)?是否要跟 5.6 的羈絆系統掛鉤(如需要羈絆對象在場才能執行復活儀式)?

### 5.5 同伴羈絆系統(提案,待你確認/調整)

這是初步設計提案,架構上盡量沿用你已經定案的機制(類別+子行動、留守被動),減少額外新增的系統複雜度。

**基本結構**:
- 因為同伴是「精心設計的少數具名角色」(5.2),羈絆關係建議走**劇本預先設定的固定配對**,而不是自由開放的 N×N 好感度矩陣——每個同伴有 1–2 組**既定的羈絆對象**(如師徒、姊妹、宿敵、暗生情愫等),關係性質由劇情/背景故事決定,不是玩家自由培養出來的
- 呼應 worldbuilding.md § 7:同伴很可能來自不同教派、選擇脫離瘋狂加入主角陣營,**羈絆關係可以巧妙利用教派背景**——例如兩個出身同教派的同伴是舊識、兩個出身敵對教派的同伴帶著芥蒂但逐漸和解,這樣羈絆系統能直接承接世界觀素材,不需要另外編一套人物關係

**羈絆等級的成長方式**:
- 兩位有羈絆的同伴**一起被帶出門探索**時,羈絆值增長(共同經歷是最自然的培養手段,也呼應 3.6「同伴是額外行動/武器」——他們本來就會一起出現在戰鬥中)
- 特定劇情節點/營地對話也可以觸發羈絆值增長,作為敘事補充

**羈絆等級解鎖的內容**:
- **連攜技(戰鬥面)**:羈絆到一定等級後,兩位同伴同時在隊時解鎖一個共享的特殊子行動(直接沿用 2.3.1–2.3.2 的類別+子行動架構,不需要新系統),機制上等同於「多一個只有特定組合才會出現的行動槽」
- **留守加成(基地面)**:兩位有羈絆的同伴**同時留守**時,5.3 的風險緩衝效果有額外加成,鼓勵玩家思考「這次出門帶誰、留誰在家一起看門」
- **死亡的羈絆連動**(回應你上週的開放問題):同伴戰死時,其羈絆對象觸發專屬反應——可以是短期的戰鬥狀態變化(悲慟/憤怒帶來的暫時增益或减益)、解鎖一段專屬劇情/支線(如羈絆對象要求協助復活,串接 5.4),讓死亡不只是「少一個角色」,而是牽動另一個角色的敘事發展

**待你確認的方向**:
- 每個同伴的羈絆對象是否固定 1 個,還是可以有多組不同性質的羈絆關係?
- 連攜技的呈現強度(只是數值加成的子行動,還是要有專屬的演出/符號動畫)?
- 是否所有同伴都必須有羈絆對象,還是允許「獨行俠」型角色沒有羈絆線?
